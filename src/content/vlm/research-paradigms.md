## 核心问题

研究不等于提出新模块并提高总分。不同范式的成果可以是**新的测量、规律、机制解释、干预方法或可靠系统行为**；每一种需要不同的证据。

## 心智模型

让几位研究者都观察到“箭头方向错”。有人设计更可靠的测试，有人找出哪些图最容易错，有人改训练数据，有人改运行时裁剪。它们可能研究同一现象，却在回答不同问题。**研究范式**就是常用的提问方式、实验方式和贡献形式，不是只根据方法名称划分论文。

## 同一个方向问题，怎样走进不同范式

### Benchmark：先把能力测准

问题可以是“现有题目混合了类别识别与方向识别，能否构造更清楚的方向测量”。工作包括定义坐标与端点、收集平衡题、复核真值和设计评分。

贡献是新的有效测量，而不只是一批更难的题。要证明旧评测遗漏了什么、新题确实依赖视觉、分数能可靠复现。[PerceptionBench](https://arxiv.org/abs/2607.24957)可用于学习原子能力测量的思路。

### Diagnosis：找错误出现的条件

诊断问“方向错误是否集中在小目标、某类形状或某类问法”。固定协议后分组、做配对和重复运行，结果可能是一条有条件的错误规律。

它不一定需要修复方法。若新规律可靠、可迁移且改变我们理解模型的方式，就有研究意义。对结果的原因解释仍要另做证据，不能从错误分布直接跳到“编码器没有空间信息”。

### Scaling 与模型家族：看变化关系

**Scaling** 可以改变参数规模、数据量或计算预算；**model family（模型家族）**通常指共享一些设计或训练路线的版本。比较同家族不同规模，仍应查分辨率、视觉编码器与后训练是否相同。

若更大版本识别上升、方向没上升，是值得验证的变化模式；若两个品牌一起换了架构、数据和训练，就只是跨系统比较。不能将参数量与分数的相关性直接解释成单一因果关系，也不能仅凭突跃分数宣称能力“涌现”，指标阈值也会制造突跃。

### Architecture：改信息进入和流动方式

把视觉编码器换掉、保留更多层特征或改变连接器，属于架构干预。要尽量匹配语言底座、训练数据和输入预算，再测具体能力与成本。

如果换编码器时也换了训练集，涨分仍是系统事实，但单个组件的贡献无法独立确定。[MM1](https://arxiv.org/abs/2403.09611)的消融可用于练习检查控制变量。

### Data-centric 与 training：改练习内容和目标

数据研究可以保持模型结构不变，增加平衡方向样本，或去掉模板线索；训练研究还可以改变目标、优化或冻结策略。它们问的是哪些学习信号塑造哪些行为。

独立对象、场景和表达上的测试很重要。只在与训练模板相似的箭头上改善，可能是在适配生成规则，而未形成可迁移的方向能力。

### Post-training：改已经预训练模型的回答策略

用 SFT 教模型输出坐标，或用奖励鼓励核对图像后答题，都可能改变行为。要测正确率、拒答、长度、延迟和其他能力有没有退化。

回答更谨慎可能降低幻觉，也可能增加拒答；奖励答对可能强化猜答案。只报告一个分数不能说明代价，训练名称也不能说明机制，见[训练页](../training/)。

### Inference-time / training-free：改运行过程

使用原图局部裁剪、翻转一致性检查或外部工具，而不更新目标权重，属于一类免训练运行方法。核心比较是新增信息与同等计算预算下的收益。

例如两次模型调用胜过一次调用，不足以证明翻转规则本身必要；至少与两次原图调用比较。方法效果与有效原因是两个贡献层次。

### Mechanistic analysis：检查内部路径

如果有模型内部访问权限，可以测颜色或方向信息在何层可读出，再替换某些激活看输出变化。**激活替换**是把一个条件产生的中间数值用于另一条件，检查特定路径是否影响回答。

这类因果干预也可能让模型收到不自然特征，或同时破坏许多功能，因此需匹配控制与替代解释。Probe 和注意力可视化是线索，单独不构成完整机制证明，详见[视觉表征](../visual-representation/)。

### Agentic：把观察接到行动与反馈

Agent 可以看界面、决定点击、读取执行后的新界面，再继续。VLA 则将视觉与语言联系到机器人动作。研究除了看图，还要看行动是否实现目标。

最后任务成功包含定位、规划、执行和环境反馈。若失败，要区分这些环节；[OSWorld](https://arxiv.org/abs/2404.07972)是交互任务测量的一个入口。不能用闭环成功率直接替代原子感知分数。

## 主要范式

| 范式 | 问什么、怎样做 | 贡献与常见误区 |
|---|---|---|
| Benchmark / evaluation | 现有测量漏了什么？设计题、标注、基线、可靠评分 | 新构念及可复现评测；只做更难题或榜单不够 |
| Diagnosis / failure / capability | 哪类输入、模型和任务稳定失败？分组、配对、控制混杂 | 可迁移的错误规律；几个个案不是系统特征 |
| Bias / robustness / scaling | 错误是否非对称？随规模、分辨率、数据、扰动怎样变化？ | 明确条件的变化规律；跨家族相关不等于因果 |
| Architecture | 改编码器、连接器、融合或 token 化 | 在匹配数据、底座与计算下归因；不能只比较不同系统 |
| Data-centric / training | 哪些数据和目标塑造哪些能力？做配比与目标消融 | 新训练规律与泛化；不能把数据量和质量混为一谈 |
| Post-training | SFT、偏好或奖励怎样改变回答、推理和工具行为？ | 稳定改进及代价；推理链变长不等于视觉更准 |
| Inference-time / training-free | 不改权重怎样验证或改善当前判断？做等预算对照 | 可复现的干预边界；多次采样不等于新证据 |
| Mechanistic / interpretability | 内部哪里表征了信息，哪条路径影响输出？probe、激活替换、因果干预 | 可证伪机制；注意力热图或 probe 单独不足以证明因果 |
| Agentic / GUI / embodied / VLA | 视觉怎样接行动与反馈？在交互环境测最终任务 | 闭环能力；成功率还包含规划、执行与环境因素 |

## 它怎样工作

常见研究链是：异常观察 → 排除标注与协议问题 → 系统表征错误 → 提出机制假设 → 做因果对照 → 如果需要，再设计训练或推理干预。顺序可以改变，但如果跳过诊断，方法涨分通常难以解释。

## 为什么重要

研究对象不同，评价标准就不同。Benchmark 应问构念效度；机制研究应问干预是否改变目标行为；系统工作应问真实任务的收益、延迟与成本。不能用同一份总分证明全部贡献。

## 容易混淆

**Training-free** 指当前方法不更新被评测模型的权重，并不排除使用已训练的 OCR 工具；**inference-time** 强调干预时点。**Mechanistic analysis** 需要超出相关性可视化的干预；内部信息“可读出”与输出“因它而改变”不同。

## 研究视角

为论文写一句贡献主张，再问：如果论文所有方法涨分都成立，它是否真的支持这句话？若只支持“在数据集 A 提高 2 分”，便不要写成“解决视觉推理”。

## 代表性工作

[MM1](https://arxiv.org/abs/2403.09611) 是组件与数据消融；[PerceptionBench](https://arxiv.org/abs/2607.24957) 是能力测量；[VLind-Bench](https://arxiv.org/abs/2406.08702) 是语言先验诊断；[工具贡献研究](https://arxiv.org/abs/2606.02357) 是 agent 消融。它们的主问题不同，不能只按排行榜比较。

## 关联与判断

自检：没有提出新模型，但通过可靠对照发现原有测量不依赖图片，有贡献吗？可能有，贡献是测量与诊断。对任何论文，先说明它想新增哪一种知识，再决定什么实验足够。
