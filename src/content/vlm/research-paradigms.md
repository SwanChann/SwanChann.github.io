## 核心问题

研究不等于提出新模块并提高总分。不同范式的成果可以是**新的测量、规律、机制解释、干预方法或可靠系统行为**；每一种需要不同的证据。

## 心智模型

按 `问题 → 典型实验 → 合格贡献 → 易犯错误` 比较路线。一个项目可以跨范式，但论文的主张要与其最强证据相匹配。

## 主要范式

| 范式 | 问什么、怎样做 | 贡献与常见误区 |
|---|---|---|
| Benchmark / evaluation | 现有测量漏了什么？设计题、标注、基线、可靠评分 | 新构念及可复现评测；只做更难题或榜单不够 |
| Diagnosis / failure / capability | 哪类输入、模型和任务稳定失败？分组、配对、控制混杂 | 可迁移的错误规律；几个个案不是系统特征 |
| Bias / robustness / scaling | 错误是否非对称？随规模、分辨率、数据、扰动怎样变化？ | 明确条件的变化规律；跨家族相关不等于因果 |
| Architecture | 改编码器、连接器、融合或 token 化 | 在匹配数据、底座与计算下归因；不能只比较不同系统 |
| Data-centric / training | 哪些数据和目标塑造哪些能力？做配比与目标消融 | 新训练规律与泛化；不能把数据量和质量混为一谈 |
| Post-training | SFT、偏好或奖励怎样改变回答、推理和工具行为？ | 稳定改进及代价；推理链变长不等于视觉更准 |
| Inference-time / training-free | 不改权重怎样验证或改善当前判断？做等预算对照 | 可复现的干预边界；多次采样不等于新证据 |
| Mechanistic / interpretability | 内部哪里表征了信息，哪条路径影响输出？probe、激活替换、因果干预 | 可证伪机制；注意力热图或 probe 单独不足以证明因果 |
| Agentic / GUI / embodied / VLA | 视觉怎样接行动与反馈？在交互环境测最终任务 | 闭环能力；成功率还包含规划、执行与环境因素 |

## 它怎样工作

常见研究链是：异常观察 → 排除标注与协议问题 → 系统表征错误 → 提出机制假设 → 做因果对照 → 如果需要，再设计训练或推理干预。顺序可以改变，但如果跳过诊断，方法涨分通常难以解释。

## 为什么重要

研究对象不同，评价标准就不同。Benchmark 应问构念效度；机制研究应问干预是否改变目标行为；系统工作应问真实任务的收益、延迟与成本。不能用同一份总分证明全部贡献。

## 容易混淆

**Training-free** 指当前方法不更新被评测模型的权重，并不排除使用已训练的 OCR 工具；**inference-time** 强调干预时点。**Mechanistic analysis** 需要超出相关性可视化的干预；内部信息“可读出”与输出“因它而改变”不同。

## 研究视角

为论文写一句贡献主张，再问：如果论文所有方法涨分都成立，它是否真的支持这句话？若只支持“在数据集 A 提高 2 分”，便不要写成“解决视觉推理”。

## 代表性工作

[MM1](https://arxiv.org/abs/2403.09611) 是组件与数据消融；[PerceptionBench](https://arxiv.org/abs/2607.24957) 是能力测量；[VLind-Bench](https://arxiv.org/abs/2406.08702) 是语言先验诊断；[工具贡献研究](https://arxiv.org/abs/2606.02357) 是 agent 消融。它们的主问题不同，不能只按排行榜比较。
