## 核心问题

不更新权重，能否让模型更可靠地使用图像？可以改变提示、图像视图、工具和计算预算，但每种干预的**新增证据**与成本不同。

## 心智模型

假设模型已经训练好，却把红项圈读错。现在不改模型权重，我们仍可以重新问、提供更清楚的区域、调用 OCR，或重复生成后汇总。它们都改变了运行过程，但新增的证据并不一样。先看每种方法实际让模型多获得了什么。

## 同一张图，六类干预怎样工作

### 改提示：改变要关注或输出的内容

**Prompt（提示）**就是发给模型的任务文字。把“描述图片”改成“只回答这只猫的项圈颜色”，减少了输出范围；要求先描述目标再回答，可能帮助对象绑定。但没有增加新的项圈像素。

**CoT**要求生成分步文字推理。对于关系组合题可能有用，但如果第一句就把红色读成蓝色，后面会在错误前提上继续推。需要分别核查中间事实和最终答案，不能只看理由是否变长。

### 标记和裁剪：改变实际可见内容

**Visual prompting（视觉提示）**可以在图片里画框或编号，告诉模型指的是哪只猫。框也可能遮住小特征，因此需要留出证据区域。

**ROI（感兴趣区域）**指当前任务相关的局部范围。Crop 从原图取出这个区域；zoom 放大它。若从原始高分辨率图重取猫颈部，再给编码器，项圈可用像素可能更多；若只是把已模糊的小图拉大，则没有恢复真实细节。

**Multi-crop / multi-view** 提供多个裁剪或视图。例如一张整图保留位置，一张局部图读颜色。需知道局部图对应整图哪只猫，否则又出现跨图绑定问题。真实不同视角可能增加新证据；同一图裁剪主要重分配输入预算。

### 外部工具：用另一套计算提供结果

OCR 工具返回标牌字符，检测器返回猫框，分割器返回区域掩码。模型把工具结果与问题结合，不代表这些工具必然正确。每种工具的错误还会传到后续答案。

比较“真 OCR 文本”“空返回”“无工具”可以检查是否真用了工具内容；还应匹配提示和可用计算预算。真工具条件更好，可能支持工具有价值，但仍需看新增信息与失败样本。[工具贡献研究](https://arxiv.org/abs/2606.02357)展示了用这类消融检查工具作用的研究思路。

### 重复生成与自一致：增加候选，不一定增加证据

**Self-consistency（自一致聚合）**可以让模型生成多次，再按多数答案汇总。教学中，五次得到“红、红、蓝、红、蓝”，多数为红。它降低某些随机输出影响，却可能让五次相同错误更稳定。

增加采样、推理步骤或工具调用预算称为一种 **test-time scaling**。研究要画出性能与调用数、延迟、成本的关系，而不是拿五次调用与一次调用的分数差单独证明算法更好。重复回答并未自动带来新图像信息。

### 翻转和旋转：检查答案是否遵守变换规则

右下箭头水平翻转后应为左下。可以分别询问原图和翻转图，将后者答案映射回原坐标系再比较。若两次互相矛盾，可以发出“当前判断不一致”的诊断信号。

但这种信号未必告诉你哪一次对，更不能默认多数变换答案是真值。需要独立评测纠错准确率、拒答效果与失败情况。具体标签规则见[空间与三维](../spatial-3d/)。

### Training-free 与 inference-time 的边界

**Training-free** 强调这次方法不更新目标模型权重；**inference-time** 强调改变发生在运行时。调用一个已经训练好的 OCR 可以同时符合两者，但并非“完全没有训练过的系统”，也不是没有成本。

如果另外训练一个判断哪次回答更可信的选择器，要明确它有额外训练；不能把全系统笼统说成无需训练。需要界定哪些模块、什么阶段、谁的参数更新了。

## 从一个方法想法走到验证

设想“局部裁剪应该修复小项圈颜色题”。先写出预测：小目标比大目标受益更多；再规定原图、裁剪选取和输出解析；比较原图、局部图和等预算多次原图；最后检查是否只是目标提示更明确。

若裁剪有用而高分辨率整图无用，可能涉及注意分配或目标绑定，不应直接宣布像素不足就是唯一原因。要把方法效果与原因解释分成两个问题。

## 关键概念

| 方法 | 改了什么 | 关键检查 |
|---|---|---|
| Prompt / CoT | 指令和生成步骤 | 是否只改变输出风格或语言先验？ |
| Visual prompting / ROI / crop / zoom | 标记或重编码局部原始像素 | 裁剪是否保留全局参照？是否真正增加有效分辨率？ |
| Multi-crop / multi-view | 提供多个互补视图 | 新视图是否带来答案关键证据？ |
| Repeated inference / self-consistency | 重采样并聚合回答 | 多数一致是否只是共同偏差？ |
| 外部 OCR / detector / segmenter | 引入专用模型输出 | 改善来自工具还是额外监督与格式？ |
| Test-time scaling | 增加推理时间或工具调用预算 | 性能、延迟、成本与幻觉如何变化？ |
| Flip / rotation / scale / contrast | 构造变换视图或一致性测试 | 标签如何按变换映射？变换是否改了题意？ |

## 它怎样工作

**Training-free** 通常指不为当前方法更新模型权重，可包括诊断、增强、纠错或推理时干预；并不意味着零计算、零外部模型或没有预先训练的工具。**Inference-time** 强调发生在推理阶段，两者高度重叠但侧重点不同。

## 为什么重要

工具调用轨迹是行为，不是工具贡献的证据。应比较真工具返回、空返回、仅调用格式、无工具、相同计算预算等设置。[2026 工具消融研究](https://arxiv.org/abs/2606.02357) 在其分析的模型与任务中发现工具带来的独有解题集合较小；不能推广为“所有工具无用”。

## 容易混淆

CoT 变长不必然提高视觉感知；模型可能在错误视觉前提上推理得更连贯。旋转或翻转可用来诊断等变性，但若坐标参照或文字内容也随之改变，标签映射不能机械套用。

## 研究视角

每个干预写四行记录：**输入新增什么**、**预期改善哪类题**、**必要对照是什么**、**失败时意味着什么**。若空工具与真工具效果相同，先检查该题是否本就可由原图或题干解决，再讨论工具设计。

## 代表性工作

[Do Multimodal Agents Really Benefit from Tool Use?](https://arxiv.org/abs/2606.02357) 是工具贡献诊断的例子；[MIRAGE](https://arxiv.org/abs/2603.21687) 提醒无图基线的重要性。[ICML 2026 position paper](https://openreview.net/forum?id=ivAHZuj8k1) 提出对中间图像做消融的主张；具体实验仍应读原文核查。

## 关联与判断

自检：重复五次与给一张新视角，新增证据相同吗？不同，前者通常重用已有输入。翻转回答不一致能直接纠错吗？不能，它首先是诊断信息，还缺哪次正确的依据。

结合[视觉表征](../visual-representation/)判断新视图能否增加证据，结合[评测](../evaluation/)设计对照。读完应能解释“方法没有训练”与“方法被证明有效”之间还缺哪些实验。
