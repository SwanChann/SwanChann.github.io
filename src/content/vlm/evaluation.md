## 核心问题

想测“模型能否看清箭头朝向”，我们不能只收集图片然后运行模型。必须规定方向怎样判定、什么答案算对、无图能否猜对，以及多次回答怎样计算分数。**Benchmark** 是这一套可复用的测量安排；dataset（数据集）是其中的样本与数据部分。

## 心智模型

先沿一题走完整个评测，再看统计表。“构念”指想测的概念，例如图像坐标下的方向识别；“构念效度”问题目和评分是否真的测到了它。箭头题若仅靠题干常识就能答对，分数对视觉方向能力的说明就很有限。

## 一道题从哪里来，怎样计分

### 1. 定义任务和真值

原图包含一个清晰箭头，人工核实尖端朝右下，写下真值 `right-down`。**Ground truth（真值）**是评测采用的参考答案，需要可靠生成或标注，不是模型最自信的回答。

模糊尖端、错误坐标系或多人无法达成一致，都应有排除或仲裁规则。人工标注也会错；模型低分前先抽样复核题和标签。

### 2. 固定模型实际看到的输入

保留原图、预处理、提示和模型精确版本。“这是什么方向”与“四个方向选一个”是不同输入协议；选项顺序还可能带偏置。记录采样参数、重复次数和工具设置，才能让他人复算。

### 3. 保存原始回答，再规范化

模型可能输出“尖端朝右下方”。程序把它规范化为 `right-down`，再与参考比较。若只做逐字符 exact match，它会因措辞不同被判错；若解析规则太宽，含矛盾理由的答案也可能误算对。

因此同时保存原始文本、解析结果和评分。格式错误、拒答、语义错误最好分别统计。不能只保留一个总正确率，让评分器问题无法追溯。

## 常见指标，用小例子算清楚

下面数字全部是虚构教学数据。

### Accuracy 与 exact match

10 道方向题答对8道，**accuracy（准确率）**为 `8/10=80%`。**Exact match（精确匹配）**要求答案按既定规范完全一致，是一种计分规则。是否先统一“右下方”和“右下”，会影响 exact match 的意义。

### Precision、recall 与 F1

假设图里实际有4只猫，系统报告3个猫目标，其中2个正确、1个误报，同时漏掉2只。**Precision（精确率）**问“报告的有多少正确”：`2/3`；**recall（召回率）**问“实际的有多少被找回”：`2/4`。

**F1** 是二者的调和平均：`2PR/(P+R)`，此例为 `4/7≈57%`。它不允许只多报或只保守少报就显得很好。但必须先定义目标匹配，例如两个框怎样算同一只猫，否则数字无从计算。

### IoU 与点距

**IoU（交并比）**是预测区域与参考区域的交集面积除以并集面积。两框各面积100、重叠50，并集是150，因此 IoU 为 `50/150=1/3`。有重叠不等于准确，达到什么阈值算命中必须预先定。

点定位可以算预测点与真值点的距离，或是否落入允许区域。若图像缩放了，像素距离也会变，所以坐标尺度需要一致或规范化。

### 开放回答怎样用 judge

**LLM-as-a-Judge** 把问题、参考、模型回答和评分规则交给另一个语言模型，由它判对错或质量。它适合多种措辞的开放答案，但本身也可能偏向长回答、自信措辞或熟悉的表达。

需要固定 judge 版本、提示和评分标准，并抽样人工检查分歧。如果它看不到原图，只能依据提供的参考事实判，不应把它当新的视觉真值来源。人类评判也要记录一致性、盲评及仲裁方式。

## 从分数到规律，缺的是什么

“方向题80%”描述一组题上的结果。进一步按左右、目标大小和图像来源拆分，才能提出某些条件是否更难。翻转配对测的是输入变化与输出变化的关系；重复测的是稳定性；无图基线检查题目是否依赖视觉。

有图比无图高，并不把差值直接变成模型的纯视觉能力：条件变化可能影响输入形式和应答策略。有图无图差别很小也不能证明它从不看图，只能限定到这些题和协议。

**数据污染**指测试题或高度相似内容进入训练，可能让高分反映记忆；**饱和**指题集太容易、分数挤在高位，难区分能力；**聚合**指把类别分数合成总分，类别数量与权重不同就会改变排名。它们都应在结论中说明。

若想谈规律，使用独立题集验证、记录统计不确定性，并预先决定主要比较。探索时找到难题很有价值，但不能在同一批精挑失败题上宣称普遍性。

## 关键概念与指标

| 指标/设计 | 适用场景 | 注意 |
|---|---|---|
| Accuracy / Exact Match | 分类、短答案 | 同义答案需规范化；格式错误与知识错误分开 |
| Precision / Recall / F1 | 检测、抽取、类别不平衡 | 先定义正例、匹配规则和分母 |
| IoU / 点距 | 框、区域或点定位 | 坐标系、分辨率和阈值必须固定 |
| LLM-as-a-Judge | 开放生成答案 | judge 版本、提示、偏好与一致性均要检查 |
| Human evaluation | 多解或主观质量 | 标注一致性、盲评和仲裁规则 |
| Pairwise / transformation | 原图与反事实图配对 | 两题都对、标签等变与一致性分别报告 |
| Category profile | 多维能力剖面 | 类别样本量与权重影响总分 |

## 它怎样工作

按能力选择题，而不是先选榜单再给分数命名。一个方向评测至少要有：明确的尖端与坐标系、平衡方向、真实与合成图、多种对象、人工检查、无图基线、翻转配对和重复运行。输出同时展示正确率、方向混淆矩阵与样本级错误。

## 为什么重要

从“跑 benchmark”到“发现规律”的关键是**对照与解释边界**。例如两个模型总分都 70%，一方 OCR 强、一方空间强；总分相等掩盖能力剖面。若无图也能高分，可能是题干泄漏、常识或答案分布让任务变得可猜。要讨论视觉贡献，应结合无图基线、改变关键视觉事实的配对题和样本级回答；只看有图与无图的总分差仍不足以定位原因。

## 容易混淆

数据污染、题型饱和、选项偏置、prompt 敏感、随机采样、答案解析和 judge 偏差均可改变分数。无法用一项总分证明通用视觉能力，也不能把某个 benchmark 的低分直接定位到编码器。

## 代表性测量

| 类型 | 例子 | 能说明什么；不能说明什么 |
|---|---|---|
| 综合多模态 | [MMMU](https://arxiv.org/abs/2311.16502) | 多领域综合解题；难以单独归因于感知 |
| 原子感知 | [PerceptionBench](https://arxiv.org/abs/2607.24957) | 特定分类下的感知剖面；不覆盖所有应用场景 |
| 空间/视觉模式 | [CV-Bench](https://arxiv.org/abs/2406.16860)、[BLINK](https://arxiv.org/abs/2404.12390)、[MMVP](https://arxiv.org/abs/2401.06209) | 选定视觉与空间题的表现；需检查题目和标签设计 |
| 幻觉与语言先验 | [VLind-Bench](https://arxiv.org/abs/2406.08702)、[MIRAGE](https://arxiv.org/abs/2603.21687) | 反事实/无图条件；不能推出模型从不看图 |
| GUI agent | [OSWorld](https://arxiv.org/abs/2404.07972) | 真实任务完成；分数还混合规划、操作和环境 |

这些例子是阅读入口。每次引用 benchmark 还应记录数据来源、指标、评判流程、模型版本，以及它**不能支持**的结论。LRR-Bench、SpatialMQA 等更专门题集可按需要加入，不凭名称先纳入统一排行榜。

## 研究视角

形成规律需通过独立图像、模型家族、提示和时间复验，并报告负结果。评测协议应允许他人从样本、原始响应与评分程序复算结果。

## 关联与判断

自检：precision 高、recall 低可能是什么情况？只报告少量确定目标，但漏了许多。总分上涨能否证明空间能力上涨？必须查看空间子题、评分协议和其他变量，而不是直接推断。
