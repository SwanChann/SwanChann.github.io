## 核心问题

Benchmark 不等于一份题库；它是**构念、样本、标注、输入协议、模型输出、评判规则和聚合方式**组成的测量系统。首先问：它声称测量的能力，是否真的决定答案？

## 心智模型

`任务定义 → 样本与真值 → prompt/inference protocol → 原始回答 → 规范化/评判 → 指标 → 结论`。任何一环改变都可能改分数。保留原始回答与运行元数据，才能在评分或分类变化后重算。

## 关键概念与指标

| 指标/设计 | 适用场景 | 注意 |
|---|---|---|
| Accuracy / Exact Match | 分类、短答案 | 同义答案需规范化；格式错误与知识错误分开 |
| Precision / Recall / F1 | 检测、抽取、类别不平衡 | 先定义正例、匹配规则和分母 |
| IoU / 点距 | 框、区域或点定位 | 坐标系、分辨率和阈值必须固定 |
| LLM-as-a-Judge | 开放生成答案 | judge 版本、提示、偏好与一致性均要检查 |
| Human evaluation | 多解或主观质量 | 标注一致性、盲评和仲裁规则 |
| Pairwise / transformation | 原图与反事实图配对 | 两题都对、标签等变与一致性分别报告 |
| Category profile | 多维能力剖面 | 类别样本量与权重影响总分 |

## 它怎样工作

按能力选择题，而不是先选榜单再给分数命名。一个方向评测至少要有：明确的尖端与坐标系、平衡方向、真实与合成图、多种对象、人工检查、无图基线、翻转配对和重复运行。输出同时展示正确率、方向混淆矩阵与样本级错误。

## 为什么重要

从“跑 benchmark”到“发现规律”的关键是**对照与解释边界**。例如两个模型总分都 70%，一方 OCR 强、一方空间强；总分相等掩盖能力剖面。若无图也能高分，题干可能泄漏答案；有图涨分才有资格讨论视觉贡献。

## 容易混淆

数据污染、题型饱和、选项偏置、prompt 敏感、随机采样、答案解析和 judge 偏差均可改变分数。无法用一项总分证明通用视觉能力，也不能把某个 benchmark 的低分直接定位到编码器。

## 代表性测量

| 类型 | 例子 | 能说明什么；不能说明什么 |
|---|---|---|
| 综合多模态 | [MMMU](https://arxiv.org/abs/2311.16502) | 多领域综合解题；难以单独归因于感知 |
| 原子感知 | [PerceptionBench](https://arxiv.org/abs/2607.24957) | 特定分类下的感知剖面；不覆盖所有应用场景 |
| 空间/视觉模式 | [CV-Bench](https://arxiv.org/abs/2406.16860)、[BLINK](https://arxiv.org/abs/2404.12390)、[MMVP](https://arxiv.org/abs/2401.06209) | 选定视觉与空间题的表现；需检查题目和标签设计 |
| 幻觉与语言先验 | [VLind-Bench](https://arxiv.org/abs/2406.08702)、[MIRAGE](https://arxiv.org/abs/2603.21687) | 反事实/无图条件；不能推出模型从不看图 |
| GUI agent | [OSWorld](https://arxiv.org/abs/2404.07972) | 真实任务完成；分数还混合规划、操作和环境 |

这些例子是阅读入口。每次引用 benchmark 还应记录数据来源、指标、评判流程、模型版本，以及它**不能支持**的结论。LRR-Bench、SpatialMQA 等更专门题集可按需要加入，不凭名称先纳入统一排行榜。

## 研究视角

形成规律需通过独立图像、模型家族、提示和时间复验，并报告负结果。评测协议应允许他人从样本、原始响应与评分程序复算结果。
