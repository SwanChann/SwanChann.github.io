## 核心问题

模型知道“这是指针”，为何仍可能把它朝向说错？物体语义可辨认与精确几何关系可辨认，是不同的表征要求。

## 心智模型

想象把猫图交给朋友，而朋友只回给你一张“猫在沙发上”的便条。你知道场景，却无法从这句话恢复项圈颜色。模型的视觉表征不是这样一张文字便条，但这个例子说明一个问题：**一种表示可以保留某些任务需要的信息，却无法支持另一些任务。** 模型的实际表示是向量，哪些细节还在，必须测量。

## 从猫的红项圈开始展开

### 原始像素与特征为什么不是同一回事

在[架构](../architecture/)的例子里，原图经过缩放与编码，形成视觉向量。原图中一个位置的 RGB 直接描述该像素颜色；特征向量的一个数则是许多输入数值经过计算的结果。不能对特征的前三个数直接当 RGB 读，也不能任意挑一个维度称为“红色维度”。

**表征**就是模型用来表达输入信息的数值形式。它可以支持分类而无需保存每个原始像素。判断“有猫”可能只需若干形状与纹理线索；判断“项圈缝线上有几个白点”需要更多局部细节。不存在一个只看向量长度就能确定“看得多清楚”的规则。

### 局部与全局分别在说什么

项圈附近的纹理是**局部信息**，猫与沙发构成的整体布局是**全局信息**。局部向量经过 attention 后，也可能含有别的区域的信息；全局向量则可以汇聚许多区域。局部/全局描述信息范围，不是给每个向量贴一个永久类别。

当我们让模型描述整张图时，“宠物在室内”这类概括可能够用；让它判断项圈颜色时，相关区域的细节就更重要。研究输入处理应同时检查这两类任务，避免局部裁剪改善颜色题却丢掉猫与沙发的相对位置。

### 语义、几何与位置是不同要求

看见一个箭头并说“这是箭头”，主要要求类别辨认，称为**语义**判断。问箭头尖端朝哪边，需要端点形状和方向关系，涉及**几何**；问箭头在猫左边还是右边，需要多个对象的位置关系，涉及**空间**。

三者可以由共享特征支持，并不是一定有三个独立网络。重要的是训练和测量要求不同：如果把所有箭头旋转后仍标为“箭头”，分类目标可以鼓励忽略方向；但方向任务恰好需要保留方向。认识物体不必然意味着这些方向信息被保留并使用。

**位置编码**给图块位置提供线索；存在位置编码不等于模型一定能回答精确坐标。若后面把许多图块平均汇总，或任务训练不要求空间关系，还要检查对应关系如何进入答案。

### “压缩”和“信息瓶颈”具体指什么

例如把很多视觉向量汇聚为较少向量，或把大图缩为小图，都减少了直接传递的细节。有限的输入或表示资源称为一种**信息瓶颈**。它是否限制某个任务，取决于哪些信息被保留，而不只是 token 数是否变少。

把 196 个 token 变成较少位置只是资源变化的例子，不能单凭此证明红色信息消失；反过来，有更多 token 也不保证细节被有效利用。需要对同一任务比较压缩前后可读出的信息和实际答案。

## 信息在、被使用、被解释：怎样分别检查

### 第一步：检查是否可以从特征读出

假设我们能拿到一批红/蓝项圈图片的编码器输出。固定编码器，用一部分样本训练一个小分类器预测颜色，再在独立图片上测试。这个小分类器称为 **probe（探针）**，因为它在探测特征里是否有可用于判断的信息。

若能在新图片上准确分辨，支持“在这个设置中颜色信息可被读出”。还要防止它其实学了背景或猫品种与颜色的相关性。不能用训练集上的高分当证据，也不能将 probe 的成功等同于原 VLM 会使用同样信息。

### 第二步：检查答案是否依赖这份信息

保持问题不变，把项圈由红变蓝，看原 VLM 的答案是否跟随改变；也可以遮住项圈或干预相关特征。**因果干预**就是有目的地改变候选因素，再观察结果变化。它比“某个特征与答案相关”更接近使用证据。

但干预也可能改变背景、视觉质量或模型输入分布，因此需要匹配对照。这里只是在建立检查思路，不能凭一次遮挡实验认定唯一原因。

### 第三步：检查文字解释是否忠实

模型回答“红色，因为我看到了红项圈”，这是一段输出文字。如果遮挡项圈后仍给同样解释，解释可能没有可靠反映视觉依据。**解释忠实性**研究的是理由与实际决定输出的过程是否一致；答案正确与理由可信需要不同证据。

这三步分别对应“可读出”“被使用”“被解释”。也因此，注意力热图只提供相关线索：热图覆盖项圈，并不自动证明答案由项圈颜色决定。

## 关键概念

- **Pixel information**：颜色与位置的原始采样；裁剪、缩放和压缩都可能改变它。
- **Local / global feature**：局部区域的纹理、边缘与全图语义；两者可能在不同层、不同 token 中呈现。
- **Semantic feature**：支持“这是什么”的表征；**geometric / spatial feature** 支持朝向、位置、距离和拓扑关系。
- **Positional information**：区域在图中的坐标或顺序；如果经过池化、重排或过度压缩，需要检查空间对应是否保留。
- **Information bottleneck**：有限视觉 token 和上下文预算迫使模型压缩输入；“哪些信息丢失”取决于任务和编码方式。

## 它怎样工作

`原始图像 → patch/切片 → encoder hidden states → connector 输出 → LLM hidden states → 答案`。每一步都可问两个不同问题：**信息可解码吗**，以及**生成答案是否因它而改变**。前者可用 probing、线性读出或特征可视化；后者需要遮挡、反事实替换、激活干预等因果对照。

## 为什么重要

分类准确率高通常证明语义判别有效，不直接证明方向、坐标或拓扑精度。反过来，单次方向错误也不能证明编码器没有方向信息，错误可能出在指代、参照系或语言映射。

## 容易混淆

**Representation ≠ usage ≠ explanation**：有信息、用了信息、文字解释忠实地描述用过的信息，是三种不同命题。注意力权重和可读推理链可以提供线索，不能单独当作因果证据。见[感知与推理](../perception-reasoning/)及[失败模式](../failure-modes/)。

## 研究视角

为“小目标朝向”建立两组配对图：类别和背景相同，只改变尖端方向；再比较高低分辨率、不同裁剪与无图对照。若性能仅随有效像素增加而改善，支持输入带宽是瓶颈之一；仍需排除提示和评分影响。

## 代表性工作

[MM1](https://arxiv.org/abs/2403.09611) 对分辨率与视觉 token 做消融；[Cambrian-1](https://arxiv.org/abs/2406.16860) 比较视觉编码器并关注 grounding。这些工作说明不能把“视觉编码器”当作不可分的黑盒。

## 关联与判断

自检：如果 probe 能分辨红蓝，但原 VLM 不随颜色改变答案，能否说编码器一定没看到颜色？不能；当前证据更支持“信息可读出，但原任务中的利用仍需检查”。如果一张原图有清晰项圈，是否足以证明模型收到清晰项圈？也不能，还需要查看实际预处理输入。

去[能力地图](../capabilities/)看不同任务要求何种证据；去[评测](../evaluation/)看怎样验证证据是否真的影响答案。读完应能区分“原图存在细节”和“模型输出因该细节而改变”。
