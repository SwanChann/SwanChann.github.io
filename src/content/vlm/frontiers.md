## 核心问题

为什么有人研究更清楚的图像，有人让模型控制电脑，还有人让它生成未来画面？它们在补不同缺口。下面用2024–2026代表性工作解释这些缺口，资料核对日期为2026-10-08；这是学习地图，不宣称穷尽所有最新论文。作者报告的能力也不等于本站已复现。

## 心智模型

从猫图开始：看清小项圈要求更多细节；看懂猫先做什么要求视频；主动裁剪项圈要求工具决策；让机器人把碗移近猫又要求行动。它们都超出“认出猫”，但新增的输入、输出与评价方式各不相同。

## 各方向在补什么，怎样检查

### 高分辨率：补小目标和细字

普通整图缩放可能抹掉项圈小字。动态分辨率、切片和更多视觉 token 让模型接触更细的输入，代价是更多计算以及跨区域对应问题。[Qwen2.5-VL](https://arxiv.org/abs/2502.13923)是阅读这类设计的一个入口。

问题不是仅有“大图能输入”，还包括小字是否读对、全局关系是否保持、每增加一份计算带来多少收益。需要细节题与全局题分别测量，见[架构](../architecture/#resolution)。

### 长视觉上下文与视频：补跨时间信息

两张照片可表达前后变化，视频可以表达过程。旧的单图问答无法判断猫吃饭前后发生什么。长上下文系统尝试接收并利用更多图片、帧和文字，例如[Qwen3-VL](https://arxiv.org/abs/2511.21631)报告了相关设计。

输入容量大并不保证关键帧被采到，也不保证正确关联同一对象。要检查实际输入、证据位置、顺序变化和长距离检索，见[多图与视频](../temporal-reasoning/)。

### 推理时计算与多模态 RL：补组合和决策

复杂图表题需要读多个值并组合；工具任务还要决定何时裁剪、何时核对。增加推理步骤和候选采样，或通过奖励训练这些策略，是不同干预位置。

**多模态 RL** 可以使用含图像观察的任务和奖励学习回答或行动策略。核心问题是奖励是否真的要求正确使用视觉证据，以及能否迁移到新场景。算术答对、过程忠实和成本可接受是不同标准，见[训练](../training/)和[推理时干预](../inference/)。

### 工具增强感知：补主动获取证据

被动接收整图时，项圈可能太小。工具系统可以选区域重看、读 OCR、检测目标，再用结果回答。Agent 的特点还包括根据反馈决定下一步，而不是固定只调用一次工具。

但写出“我调用了放大工具”不证明返回内容有贡献。真结果、空结果与无工具消融可以检查信息作用。[2026工具贡献研究](https://arxiv.org/abs/2606.02357)提供这种提问方式的例子；结论应限定其模型、工具和任务。

### GUI / computer use：补视觉到数字行动

让模型保存一份文档，需要从屏幕找到控件、决定操作、点击或输入，再检查结果。只读对“保存”文字还不够，按钮位置、状态、弹窗和执行反馈都可能影响成功。

评测如[OSWorld](https://arxiv.org/abs/2404.07972)测交互任务。因此要分别看视觉定位、规划和执行，不能用总任务成功率给 vision encoder 单独打分。

### 空间、3D与具身：补真实世界的坐标和约束

让机器人把碗移到猫旁边，需要真实位置、可达范围和碰撞约束。图片中的左右关系只是起点，真实距离和物体遮挡还可能需要深度、多视角或行动后新观察。

**Embodied AI（具身智能）**强调在环境中感知、行动和利用反馈。**VLA**将视觉、语言与动作建模联系起来；[OpenVLA](https://arxiv.org/abs/2406.09246)提供用视觉语言基础和机器人示范训练动作模型的实例。该模型的机器人任务结果不能直接推广为所有VLM拥有通用3D理解。

### Native 与 unified：补不同任务系统之间的断开

**Native multimodal** 常指作者从训练或建模起点整合多模态的设计，而不是唯一技术标准。它不保证不用视觉编码器或连接模块，必须看公开结构。

**Unified understanding + generation** 希望一个系统既理解“猫在哪里”，也能按文字生成猫图。视觉理解强调保留辨认信息，图像生成还要产生可解码的图像表示，任务要求不同。统一语言主干也可以保留不同视觉路径。[Janus-Pro](https://arxiv.org/abs/2501.17811)是统一理解与生成的代表案例；不能把“统一”简单理解成所有部件都共用。

需要检验联合训练是否互相帮助、是否某任务退化，以及生成画面是否满足指定关系。会画猫不证明能准确读每张真实猫图。

### World model：补对变化后果的预测

**世界模型**尝试预测未来观察或内部状态；有些还以候选动作作为条件，例如“推这个碗后，场景会怎样变化”。输出可以是画面，也可以是特征，不必是一段文字。

[V-JEPA 2](https://arxiv.org/abs/2506.09985)提供从视频学习表示、预测以及行动条件规划的实例。它说明这条方向存在具体方法，但不等于所有世界模型都是VLM，也不等于模型已获得完整物理规律。

核心检查是预测在未见场景中是否正确，以及用它选行动是否改善真实闭环任务。未来视频看起来逼真、离线预测误差低和机器人成功率高，是不同证据。

## 学前沿论文时如何保持判断

先问旧任务缺哪份信息或哪种反馈，再问作者增加了架构、数据、后训练还是运行时计算。若多个因素同时改变，系统提升可以成立，但单个因素的原因解释仍需消融。以下速查表用于回顾，不替代上面的具体理解。

## 方向与未解问题

| 方向 | 为什么出现 / 试图解决什么 | 仍需检验什么 |
|---|---|---|
| 高分辨率与动态视觉 token | 小目标、OCR、文档细节在缩放后丢失 | 细节改善是否足以支付 token 成本；全局关系有无退化 |
| 长图文上下文、多图和视频 | 单图无法表达跨时间/跨视角事件 | 关键帧是否被看到，时序推理是否只靠语言先验 |
| 多模态推理与 test-time compute | 复杂题需组合多个视觉事实 | 更长推理是否真正保持视觉 grounding |
| 工具增强感知与 agent | crop、OCR、检测器可提供局部证据 | 真工具输出是否比空结果或调用格式带来独有收益 |
| 空间、3D、具身与 VLA | 视觉答案要转成坐标、动作和反馈 | 单图可判定性、跨视角一致性与闭环收益 |
| 原生/统一多模态模型 | 减少理解、生成、视频和动作之间割裂 | 统一架构是否带来可测泛化，而非只合并任务接口 |

## 它怎样工作

将一篇新论文先放入上述瓶颈，再看干预位置：架构、数据、后训练或推理时。若多个地方同时改动，结论应限于整体系统，不能归因于其中一项。

## 为什么重要

同一个词如“空间智能”可指 2D 方位、3D 估计、导航或行动规划。范围越宽，越需要拆开输入、输出和评测环境。GUI agent 的任务成功率同样混合视觉定位、规划、点击执行和环境状态。

## 容易混淆

论文称“native multimodal”或“reasoning model”是作者的设计描述，不自动证明视觉与语言能力已经统一。闭源产品的内部架构不公开时，只讨论可观察行为与官方公开信息，不反推隐藏实现。

## 研究视角

追新工作时固定问：旧方法在哪类题失败？新方法新增什么视觉信息？无图、空工具、同预算和跨域对照各会怎样改变结论？

## 代表性工作

[Qwen2.5-VL 技术报告](https://arxiv.org/abs/2502.13923) 讨论动态分辨率、定位、文档和视频；[Qwen3-VL 技术报告](https://arxiv.org/abs/2511.21631) 报告长上下文及多层视觉特征设计；[OSWorld](https://arxiv.org/abs/2404.07972) 提供交互任务评测；[2026 工具研究](https://arxiv.org/abs/2606.02357) 质疑工具调用等于工具贡献的推断。这里均为作者报告，未经本站复现。

## 关联与判断

自检：能生成逼真的未来画面，是否证明能可靠控制机器人？还缺动作条件、预测有效性和闭环任务证据。输入一小时视频，是否证明理解了每个事件？还需检查采样与检索。

需要判断一篇前沿论文的贡献时，使用[研究范式](../research-paradigms/)与[论文阅读模板](../paper-reading/)，不要只看摘要里的性能宣称。
