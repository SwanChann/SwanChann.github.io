## 核心问题

快速变化的工作应按**它尝试消除什么瓶颈**来理解，而不是按“十大趋势”或产品排名记忆。下面是截至 2026-09 的研究方向图；每项都仍有评测与因果归因问题。

## 心智模型

四条主线：扩大视觉输入带宽、延长多模态上下文、让模型在推理中主动获取证据、将视觉判断连接到行动与反馈。主线之间可以组合，但任务分数的变化未必来自被宣称的模块。

## 方向与未解问题

| 方向 | 为什么出现 / 试图解决什么 | 仍需检验什么 |
|---|---|---|
| 高分辨率与动态视觉 token | 小目标、OCR、文档细节在缩放后丢失 | 细节改善是否足以支付 token 成本；全局关系有无退化 |
| 长图文上下文、多图和视频 | 单图无法表达跨时间/跨视角事件 | 关键帧是否被看到，时序推理是否只靠语言先验 |
| 多模态推理与 test-time compute | 复杂题需组合多个视觉事实 | 更长推理是否真正保持视觉 grounding |
| 工具增强感知与 agent | crop、OCR、检测器可提供局部证据 | 真工具输出是否比空结果或调用格式带来独有收益 |
| 空间、3D、具身与 VLA | 视觉答案要转成坐标、动作和反馈 | 单图可判定性、跨视角一致性与闭环收益 |
| 原生/统一多模态模型 | 减少理解、生成、视频和动作之间割裂 | 统一架构是否带来可测泛化，而非只合并任务接口 |

## 它怎样工作

将一篇新论文先放入上述瓶颈，再看干预位置：架构、数据、后训练或推理时。若多个地方同时改动，结论应限于整体系统，不能归因于其中一项。

## 为什么重要

同一个词如“空间智能”可指 2D 方位、3D 估计、导航或行动规划。范围越宽，越需要拆开输入、输出和评测环境。GUI agent 的任务成功率同样混合视觉定位、规划、点击执行和环境状态。

## 容易混淆

论文称“native multimodal”或“reasoning model”是作者的设计描述，不自动证明视觉与语言能力已经统一。闭源产品的内部架构不公开时，只讨论可观察行为与官方公开信息，不反推隐藏实现。

## 研究视角

追新工作时固定问：旧方法在哪类题失败？新方法新增什么视觉信息？无图、空工具、同预算和跨域对照各会怎样改变结论？

## 代表性工作

[Qwen2.5-VL 技术报告](https://arxiv.org/abs/2502.13923) 讨论动态分辨率、定位、文档和视频；[Qwen3-VL 技术报告](https://arxiv.org/abs/2511.21631) 报告长上下文及多层视觉特征设计；[OSWorld](https://arxiv.org/abs/2404.07972) 提供交互任务评测；[2026 工具研究](https://arxiv.org/abs/2606.02357) 质疑工具调用等于工具贡献的推断。这里均为作者报告，未经本站复现。
