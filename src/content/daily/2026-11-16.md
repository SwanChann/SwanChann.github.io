## 1. MOCAP4ROS2 2.0.0 发布：统一动捕接口，补齐机器人真值评估工具

项目作者于北京时间 **11 月 15 日 16:19** 宣布发布 MOCAP4ROS2 2.0.0。新版以统一接口连接 OptiTrack、Vicon、Qualisys 和 Gazebo，覆盖标记点、刚体和骨架数据，并新增命令行、实时延迟监测、机器人标定及在线轨迹误差评估工具。[作者发布公告](https://discourse.openrobotics.org/t/mocap4ros2-2-0-0-released-one-interface-for-optitrack-vicon-qualisys-and-gazebo-new-tools-and-website/59801)

对具身研究而言，它的价值在于减少不同动捕系统之间的数据适配工作，让定位和轨迹跟踪实验更容易获得统一真值。它不是新策略模型，也不直接证明机器人任务成功率提高。

迁移时需要留意消息包由 mocap4r2_msgs 改为 mocap4r2_interfaces。公告说明二进制包要等各 ROS 发行版下一次同步，当前可从源码构建，不能把发布公告等同于所有发行版均已可直接安装。[版本化文档](https://mocap4ros2-project.github.io/)

## 2. Qwen Code Desktop 0.27.4：扩展托管会话与飞书交付，修复权限及依赖问题

北京时间 **11 月 15 日 16:43**，Qwen Code Desktop 发布 0.27.4。版本加入客户端文件系统接入托管会话、长回复按顺序分段交付，以及飞书自定义机器人 Webhook 发送；同时新增逐轮 hook 执行记录与查询、工作区记忆导入接口。[官方发布说明](https://github.com/QwenLM/qwen-code/releases/tag/desktop-v0.27.4)

权限方面，更新包括在 AUTO 分类中判断用户授权、标示 Full Access 的风险，以及修复 MCP、DOMPurify、压缩请求解析等依赖安全问题。这些是产品工程和安全修复，不是基础模型能力升级。

工程意义是让编码 Agent 更容易接入实际工作环境，并留下可检查的执行记录。准备升级时，应优先验证现有任务的文件访问范围、消息交付和 hook 行为，而不是只比较回答质量。
