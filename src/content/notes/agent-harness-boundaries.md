源于模型与 Harness 的区别、Agent 与 Pipeline 层级的讨论。这里给出用于分析系统的工作定义，不把术语当成统一行业标准。

## 从一个具体动作看边界

假设系统要判断图片中的零件是否损坏。模型提出“裁剪右上区域”，运行环境检查参数并调用裁剪工具，工具返回局部图，模型再判断下一步。产生调用意图、执行调用、保存结果和决定是否继续，分别是不同职责。

| 概念 | 本文采用的含义 | 典型检查问题 |
| --- | --- | --- |
| 模型 | 把当前输入映射为预测或生成结果 | 输入是否包含需要的证据？ |
| Harness | 包围模型的执行与反馈设施 | 工具、上下文、权限、日志如何接入？ |
| 工作流 / Pipeline | 步骤与数据如何组织 | 分支是否预定义，失败怎样处理？ |
| Agent | 能根据反馈选择下一步行动的系统 | 能选择哪些动作，何时结束？ |

Harness 的用法在不同项目中有所不同：有时强调评测设施，有时指 Agent 的运行外壳。因此，不宜画成唯一正确的“模型小于 Harness 小于 Agent”嵌套关系。

## 动态选择与固定流程

[Anthropic 的工程说明](https://www.anthropic.com/research/building-effective-agents) 用预定义代码路径与模型动态控制流程，区分工作流和 Agent。这是有用的分析视角。实际系统可以混合两者：外层步骤固定，某个证据收集步骤允许模型选择工具。

固定流程也可以复杂、可靠；动态流程也可能重复调用工具而没有获得新信息。评价重点应是任务成功率、延迟、可观察的失败和恢复能力，而不是名称是否更“自主”。

## 怎样判断改进来自哪里

比较两个系统时，尽量固定任务、数据和预算。只换模型，观察预测质量；只换工具接口，观察调用有效性；只换上下文管理，观察遗漏和污染；只换控制策略，观察工具收益与终止时机。多个因素一起变化时，系统整体变好不等于基础模型变强。

在视觉任务中，可先实现“整图判断—必要时裁剪—复判”的明确流程，再观察失败是否需要动态扩展。若只是坐标格式错或图像分辨率不足，增加 Agent 层次并不能直接解决问题。
